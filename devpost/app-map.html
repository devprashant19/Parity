Parity — Application Architecture & Route Map

An evidence-first, pre-submission packet verification system designed to eliminate silent disqualifications in academic and financial aid applications.

LAYER 1 Perception (AI Extraction)

Strict Responsibility: Read document scans; extract values and verbatim quotes. Never decide matches.

  • Input: Multi-page PDF or JPEG/PNG document scans.
  • Route: POST /api/extract
  • Models: Primary gemini-3.1-flash-lite with fallback to gemini-2.5-flash.
  • Output: Field values, verbatim quotes (≤200 chars), normalized bounding boxes, confidence scores.
  • Double-Read Verification: Isolated full-width horizontal crop band (±1 row) verified via secondary batched API call.

LAYER 2 Judgment (Deterministic Engine)

Strict Responsibility: Normalization, containment verification, and tri-state parity evaluation.

  • Quote Containment: Validates that extracted values literally occur within quoted snippets.
  • Normalizers: Date formats (DMY/MDY/ISO), currency and frequency annualization (weekly ×52, biweekly ×26, monthly ×12), cultural name tokenization and accent folding.
  • Status Precedence: Conflict > Needs Review > Consistent
  • Zero Hallucination: Math and logic exclusively evaluate matches.

LAYER 3 Inspection & Human Authority

Strict Responsibility: Side-by-side evidence inspection, applicant authority, and remediation.

  • Inspection Drawer: Side-by-side verbatim quotes, diff callouts, visual bounding box overlays.
  • Decision Controls: Applicant chooses authoritative document (“Document A is correct” / “Document B is correct”).
  • Actionable Fix Plan: Prioritized remediation advice (edit application form vs request official certificate correction).
  • Offline Artifacts: Downloadable PDF verification report and drafted correction request letter to registrar.

Application Data Flow

  1. Document Ingestion: User selects a sample preset (e.g. USD Scholarship or EUR/GBP packet) or uploads custom files.
  2. Extraction: Fast client path runs offline from cached fixtures; live path calls POST /api/extract with multi-part images.
  3. Verification Engine: Deterministic engine (src/lib/compare/engine.ts) processes extracted records against schema definition.
  4. Double-Read Verification: For fields preliminarily marked Consistent, crops are generated and sent in one batched call per document. Visual overlays are displayed only if crops agree; otherwise marked “Location not verified”.
  5. Interactive Resolution: User inspects discrepancies in EvidenceDrawer, selects authoritative documents, and exports audit records.
Parity • Built with Next.js 15, TypeScript, Tailwind CSS, and Google Gemini Multimodal APIs.
